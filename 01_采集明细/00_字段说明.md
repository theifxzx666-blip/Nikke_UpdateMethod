## 一、三张表的分工

| 表 | 行数 | 一行 = | 用来回答 |
| :--- | :-: | :--- | :--- |
| `采集明细_<期次>.csv` | 263 | 一个**交付素材** | 这个文件从哪个键、哪个包、用什么方式来的？值不值得留？ |
| `全量文件_<期次>.csv` | 1,598 | 一个**文件** | 总共交了多少东西？哪些没进素材表（文本/表格/说明）？ |
| `采集明细_总表.csv` | 36 | 一个**分类 × 类型** | 每类多少张、多少 MB、多少是 P0？**所有对外数字的唯一出处** |

**为什么要两张明细表**（E-22）：`_素材清单.csv` 只登记二进制素材（图/动画/模型），不登记 txt/tsv/md。
本期清单 263 行，全量表 1,598 行，差的 1,335 个是剧情文本（887 个 txt）、语音（126 个 wav）、
BGM（11 个 mp3 + 11 个 wav）、表格（50 个 tsv）、说明（29 个 md）、地图 json、glb 等。
把清单当全量清单用，验收「行数=文件数」永远对不上。

## 三、`来源键` 怎么来的（四条规则，全部可复现）

**① 从既有清单 join**（首选，最准）
- `07_角色爆裂特写` → `00_汇总.tsv` 的 `相对路径 → 资源ID`
- `06_角色大厅站立动画` → 文件名 `^(c\d+_\d+)_(idle|action)`
- `05_主线_47-48章/07_关卡莱彻/动图` → `动图/00_说明.md` 第二张表 `GIF → glb`（12 行）

**② 从目录名/文件名正则**（目录名本身是实测产物）
| 分类 | 规则 | 例 |
| :--- | :--- | :--- |
| 01_新角色 | 目录名尾 `_c<ID>` → `c<ID>_00`（默认时装） | `QUEEN（真）_c870` → `c870_00` |
| 02_新皮肤 | 目录名尾 `_c<ID>_<NN>` | `冬日雅居_c871_02` → `c871_02` |
| 03_活动 | 目录名 `（ce<NNN>）` | `（ce009）` → `ce009` |
| 04_卡池横幅 | `GACHA_(C<ID>_<NN>)` → `c<ID>_<NN>`；`<名>_PASS` → 名字本身 | `GACHA_C870` → `c870_00` |
| 05 章节预告图 | 文件名去 `_S` 去后缀 | `EVENT_BANNER_TRAILMARKER_01` |
| 05 关卡莱彻 | `([a-z]{3}\d{3})_(\d)phase` 或中文名经 ① 映射 | `eba002_2phase_intro_01` |

**③ `派生`** —— 本来就没有单一来源键。判定：文件名以 `00_` 开头，或含「说明 / 清单 / 一览 / 预览 / 拼图」，
或后缀为 `.md` / `.html` / `.js`。本期 11 条。

**④ 空** —— 应溯源但读不出。**本期 0 条**。出现非 0 就要查，这是脚本或命名出了问题。

## 四、`类型` 与清单 `kind` 的差异（E-04）

清单的 `kind` 是登记时的粗分类，直接数会得出错误数字。本期实例：

| 清单 `kind` | 条数 | 实际含义 | 真实贴图数 |
| :--- | ---: | :--- | ---: |
| `爆裂特写贴图` | **99** | 混了 3 张角色图集、3 张分层时序图、9 个时序 tsv、3 个汇总说明 | **84** |

所以 `07_角色爆裂特写` 的类型**直接读 `00_汇总.tsv` 的「类别」列**，不按文件名猜
（`c872_skillcut_00.png` 就不以 `_skillcut.png` 结尾，靠文件名猜会漏）。

脚本里带交叉校验：

```
交叉校验 贴图数：汇总表 QUEEN（真）_c870=15 + 雪子_c871=42 + 埃癸斯_c872=27 = 84｜明细表 分类贴图 84  → OK
```

**不一致就说明口径又分裂了，先修脚本再出文档。**

## 五、`来源包` 为空是什么意思

本期 252 条实体键中 **208 条有包名（82.5%）**，44 条为空，全部是这三类：

| 类 | 条数 | 为什么为空 | 怎么补 |
| :--- | ---: | :--- | :--- |
| 活动资源（插画 / 教学图 / 道具 / 图标 / 敌人） | 31 | 包名不含活动代号 `ce009`，`catalog` 里没有「代号 → 包」的规则 | `locate.py <键>` 反查；或从 `03_活动/…/活动说明.md` 的键记录里取 |
| 卡池横幅 / 章节预告图 | 12 | 来自 `lss` 的 `sprite` 表，不是 bundle | 记 `lss:sprite:<name>` 即可 |
| 其余 | 1 | — | 同上 |

**空 ≠ 没查到源**。`来源键` 有值、`提取方式` 有值，就能复现；`来源包` 只是加速定位。

## 七、用法

```bash
# 预演（只报告，不落盘）
"$VENV_PY" build_inventory.py --root "…/03_历史/20260813_国际服"

# 落盘到 版本更新/01_采集明细/
"$VENV_PY" build_inventory.py --root "…/04_作业区/20261029_国际服" --write
```

**下期要改的只有一处**：脚本顶部 `CLIENT_VER`。
`BASE_KEYS`（包索引）如路径变了也要同步改，改完先跑一次预演看「有来源包」比例是否仍 >80%。

## 八、三条使用纪律

1. **对外写数字，只从 `采集明细_总表.csv` 取**，不在这里加总、不在文档里手算（E-03）。
2. **`来源键` 为空且不是 `派生`，当作 bug 处理**，不许绕过。
3. **清单变了就重跑脚本**，不手改 CSV（E-20）。
