### 4.4 战斗场景改用 `Nikke_ChargeMap`（必改，方法错过一次）

**旧流程用主线 `scan_charge_multi.py`，是「枪口角度域」扫描 —— 有系统性偏差，不是精度不够。**

> **但错的是假设，不是角度这个量**：把它拆成「枚举枪口角 + 另算准星像素」就等价了。
> 47/48 章 cityforest 三套就是这么做的，反算验证 `yaw 4.75° ↔ pixel 799.6`，视差 4.77° 与
> `atan(1.2/14.33) = 4.79°` 吻合到 0.02°。详见 `01_采集Prompt.md` §7.5.8。

| 量 | 值 |
| :--- | :--- |
| 相机位 | 角色身后 4.5 m、右偏 1.2 m、高 0.89 m |
| 枪口位 | 在角色身上 |
| 近景 15 m 偏差 | 1.2 m 横移 = **4.6° ≈ 80 px** |

→ 老脚本报「yaw −43.5 有 3 段」，玩家照做打不到。**换成像素域选点**：
<https://github.com/theifxzx666-blip/Nikke_ChargeMap>（`数据/scan_px.py`，已验证 130 个点）。

**链路**：`build_assembly.py <bundle> <out.json>`（位置参数，README 的 `001` 写法是旧的）
→ `export_glb.py` → `scan_px.py <编号> --min-multi=2` → `verify_px.py --sim=300` → `audit_px.py`

**开工前唯一必须确认的技术前提**：仓库 commit ≥ **`2a3e882`**（2026-10-26）。

```bash
git -C "$WORK/chargemap" log -1 --oneline     # 低于 2a3e882 就 git pull
```

低于这个版本会踩一个**不报错但算错数**的坑：`build_assembly.py` 的 `z=zmin` 层过滤把盒状件的
**侧壁三角形丢了**（实测单件只剩 24.5%），遮挡失效 → **段数偏高**。
三个 cityforest 包修复前 3,968 / 2,528 / 4,663，修复后 **15,614 / 9,748 / 18,500**；
修复后与另一份独立实现（走 `MeshHelper`）的 props / 三角面 / 分组 / 分层逐项一致。

**装配完的一步自检**（不用懂原理）：

```bash
# 三角面 / 顶点 比值。实测全取 ≈ 1.88、只取一层 ≈ 0.91；门限 < 1.5 判失败
```

> 顺带清掉一个旧误判：`build_assembly.py` **本来就能读** cityforest（走 `read_typetree` 的 `m_DataSize`，
> 不依赖高层 `m_Vertices`）。`m_Vertices is None` 不代表包坏了。
> **不需要 `MeshHelper` 补丁，也不需要 `asm2assembly` 适配器。**

**分级只认 S/A** —— `audit_px.py` 按六项独立审计给 S/A/B/C/D，A 级及以上才能写成「照着打」。
详见 `01_采集Prompt.md` §7.5.8。

## 五、四条口径铁律（从国服 9-30 那轮带回来的）

### 铁律 1 · 判范围只认「公告 ∩ 新增」

国服实测：一次大更的 diff 有 2,388 条新增，其中一半以上是**下期预告**（联动角色全套 + 21 个预埋角色 + 复刻活动 UI）。

```
本期采集范围 = 官方公告条目 ∩ 键 diff 新增
预埋（包内有、公告无）→ 只登记，不采集
```

### 铁律 2 · 三档口径不许混

| 档 | 定义 | 算不算本期新增 |
| :--- | :--- | :--: |
| **新增** | 键集合差里首次出现 | ✅ |
| **变更** | 键存在但 hash 变了（老资源重打包） | ❌ 不算新增，但要登记 |
| **预埋** | 包内有、公告无 | ❌ 只登记 |

> 国服那轮就是拿「变更」当新增，结论放大一倍以上。

### 铁律 3 · 时装件数能反推获取方式

国服实测规律：

| 件数 | 内容 | 对应获取方式 |
| :-- | :--- | :--- |
| **六件套** | 立绘 + 半身像 + 小人 + 爆裂特写 + 动态壁纸 + 抽取 UI | **时装抽取（Gacha）** |
| **三件套** | 立绘 + 半身像 + 小人 | **Pass / 签到赠送** |

本期正好 2 抽 + 2 Pass，是个现成的验证机会：
- `Last Affection` / `Lacrimosa` 若不足六件 → 查是不是漏了壁纸或抽取 UI
- `Dear Grace` / `Trivisa` 若是六件 → 判定可能错了，回头核获取方式

### 铁律 4 · 「官方说新增」≠「包里有变化」

本期已有实例：西班牙语（§0.3），es 列本来就是 100%。
同类还有：纯服务端配置、纯 UI 入口开关、只在服务端列表里加一行的排期。

> 处理：每条公告条目都要写「包内证据 = 有 / 无 / 零变化」，**不许因为官方说了就假装采到了**。
