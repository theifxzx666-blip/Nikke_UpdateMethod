## 五、四条口径铁律（从国服 9-30 那轮带回来的）

### 铁律 1 · 判范围只认「公告 ∩ 新增」

国服实测：一次大更的 diff 有 2,388 条新增，其中一半以上是**下期预告**（联动角色全套 + 21 个预埋角色 + 复刻活动 UI）。
国际服四周年体量更大，预埋只会更多。

```
本期采集范围 = 官方公告条目 ∩ 键 diff 新增
预埋（包内有、公告无）→ 只登记，不采集
```

### 铁律 2 · 三档口径不许混

| 档 | 定义 | 算不算本期新增 |
| :--- | :--- | :--: |
| **新增** | 键集合差里首次出现 | ✅ |
| **变更** | 键存在但 hash 变了（老资源重打包） | ❌ 不算新增，但要登记 |
| **预埋** | 包内有、公告无 | ❌ 只登记 |

> 国服那轮就是拿「变更」当新增，结论放大一倍以上。

### 铁律 3 · 时装件数能反推获取方式

国服实测规律：

| 件数 | 内容 | 对应获取方式 |
| :-- | :--- | :--- |
| **六件套** | 立绘 + 半身像 + 小人 + 爆裂特写 + 动态壁纸 + 抽取 UI | **时装抽取（Gacha）** |
| **三件套** | 立绘 + 半身像 + 小人 | **Pass / 签到赠送** |

本期正好 2 抽 + 2 Pass，是个现成的验证机会：
- `Last Affection` / `Lacrimosa` 若不足六件 → 查是不是漏了壁纸或抽取 UI
- `Dear Grace` / `Trivisa` 若是六件 → 判定可能错了，回头核获取方式

### 铁律 4 · 「官方说新增」≠「包里有变化」

本期已有实例：西班牙语（§0.3），es 列本来就是 100%。
同类还有：纯服务端配置、纯 UI 入口开关、只在服务端列表里加一行的排期。

> 处理：每条公告条目都要写「包内证据 = 有 / 无 / 零变化」，**不许因为官方说了就假装采到了**。

## 五之二、落盘裁决（原件入库，版本节点只放分类视图）

用户要求「资源归入资源库 + 额外一个文件夹按类存放」，这两条与「防重复采集」天然冲突。**裁决如下，不许自行选一个**：

- **原文件唯一落盘**在 `00_资源库\` 的类型目录（`00_资源库\角色立绘HD\` / `00_资源库\头像框\` / `00_资源库\称号\` / `00_资源库\剧情插画\` / `00_资源库\Spine\` …），沿用既有命名规范；

> 用户若另有裁决，以用户为准，并在 `00_版本说明.md` 登记冲突与最终决定。**禁止用 `robocopy /MOVE` 搬目录**（先复制再删，硬链接全断，体积翻倍 —— 见 `技术选型.md` §四）。
