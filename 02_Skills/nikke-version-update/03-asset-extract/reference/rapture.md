# 莱彻与关底 BOSS

## 一、为什么 3D 模型要渲成「立绘」

这批莱彻在客户端里是 `SkinnedMesh` + 骨骼动画，**没有 2D 立绘资产**。
所以「莱彻立绘」不是取出来的，是渲出来的。

绑定姿态下 `bone_world @ bindpose⁻¹ = 单位矩阵`，蒙皮顶点就等于原始顶点。
因此把 Mesh 顶点按 Transform 层级摆到世界空间、正交投影、按 UV 采样贴图，
得到的就是模型在绑定姿态下的正面静帧 —— 这与「骨骼还原成立绘」是同一件事。

```
python render_monster_standee.py <型号>     # 不带参渲全部
```

## 二、型号 ↔ Id 不能按字符串规律推

看着有规律，实际不是一套：

| 型号 | Id | 是否符合 `x__00N → 4X__N01` |
| :--- | :--- | :--- |
| `xmg001` | `42200101` | ✅ |
| `xma003` | `42100301` | ✅ |
| `xeg006` | `43200601` | ✅ |
| `xea003` | `43100301` | ✅ |
| `eea002` | `23100201` | ❌ |
| `mmg005` | `32200501` | ❌ |

**一律走表查**：`MonsterFieldTable` / `MonsterPartsTable`，不推算。

## 三、两阶段是两份包，不是一份的两个动画

关底 BOSS 每个阶段一套模型 + 一套 idle。缺一个阶段就是残档。

```
pull_boss_assets.py     # 批量：模型 + 两阶段 idle，按语义命名落地
pull_boss_extra.py      # 补：表演类动画 appearance / intro / skill_idle
pull_boss_map.py        # 大地图 / 单挑版模型（与关卡内不是同一份）
```

## 四、核心看不见是正常的

绑定姿态下部分装配件（最典型 `cm_core` 能量核心）被外壳**完全包裹**，
正常立绘里可见像素为 0 —— 看起来像「缺了核心」，其实是渲染角度问题。

```
python render_monster_xray.py    # 外壳 30% 透明 + 逐件拆解图
```

半透明是**渲染手法**，不是原始材质。报告里要写明，别让人以为是游戏里的效果。

## 五、直出 vs 蒙皮必须验一次

```
python verify_skin.py
```

```
V_direct = SMR.worldMatrix @ V
V_skin   = Σ w_i @ (bone_i.worldMatrix @ bindpose_i⁻¹) @ V
```

两者一致 → 直出没问题；偏差大 → 必须做蒙皮，否则部件错位。
**这一条只验一次就够**（同一套骨架），但换章节/换 BOSS 骨架要重验。

## 六、中文名：代号是主键，中文名是附加列

`Locale_Monster` 国际服实测 **929,792 B / 3,209 行 / 11 语**
（`Key, ko, en, ja, zh-TW, zh-CN, de, th, fr, es, IsSmart`）。

取名只能走 `_name`：

| 键形态 | 条数 | 说明 |
| :--- | --: | :--- |
| `<8 位>_name` | 131 | **最干净，0 条带 `[阵营]`**，首选 |
| `<10 位>_name` | — | 带 `[H.S.T.A.]` 等后缀，需 `re.sub(r'\s*\[[^\]]*\]\s*$', '', s)` |
| `_appearance_name` | 854 | **只有 2 条含中文**，其余是英文内部代号（`Trumpet` / `Mosquito`），**不能用来取中文名** |

交付用代号当主键，中文名另起一列（简繁双列），例：

```
立绘/13_xba003_安尼希利奥.png
```

## 七、大地图上的莱彻要从模型包反查

关卡内出现的 ≠ 大地图出现的。关卡表给的是 `FieldMonsterId`，
大地图要扫模型包才知道真实上了哪几个：

```
python scan_map_monsters.py     # 输出 型号 / 出现次数 / 中文名 / Grade / Size
```

47/48 章实测：关卡内 8 种 + 大地图 6 种（去重后 12）+ 关底 BOSS 2 种。
