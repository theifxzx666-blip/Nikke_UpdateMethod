# 国际服包结构与偏移（152.8.7 实测）

> 国际服与国服**布局完全不同**。国服是 `runtime_data/cache/<A>/<B>/__data` 直出 bundle，
> 国际服是内容寻址存储（`store.cdb` + `.idx`）。混用会一步都走不通。

---

## 一、目录

```
/storage/emulated/0/Android/data/com.proximabeta.nikke/files/
├── com.shiftup.addressables/
│   └── catalog.db                       # NKDB 格式，8.5 MB，AES-OFB + zlib
└── com.shiftup.patch/
    ├── core/{catalog.ndb, catalog.ndb.nds, raw\, chunk\}
    ├── dp/   同上
    ├── saus/ 同上
    ├── ja/   同上
    ├── fd/   同上
    ├── en/   只有 catalog.ndb（轻量桶）
    └── ko/   只有 catalog.ndb
```

`chunk\store.cdb` 是内容寻址大文件，`chunk\store.cdb.idx` 是它的索引。
**没有独立 bundle 文件**。

---

## 二、catalog.ndb → SQLite

解密算法同 `nkdb_dec.py`（AES-OFB + zlib）。解出来是 SQLite，三张关键表：

### `files_chunktype`

| 字段 | 含义 |
| :--- | :--- |
| `key` | bundle 名，如 `spotskillcutscene_assets_c871_00_cut_scene_18e7….bundle` |
| `file_id` | 内部文件 id |

### `chunk_file_map`

| 字段 | 含义 |
| :--- | :--- |
| `file_id` | 对应 `files_chunktype.file_id` |
| `file_offset` | 该 chunk 在**拼装后文件**里的偏移 |
| `chunk_id` | 指向 `chunks.chunk_id` |

### `chunks`

| 字段 | 含义 |
| :--- | :--- |
| `chunk_id` | 主键 |
| `hash` | 16 字节，`.idx` 的查找键 |
| `compressed_size` | store 里占多少字节 |
| `original_size` | 解压后多少字节 |

---

## 三、`store.cdb.idx`

| 段 | 长度 | 说明 |
| :--- | :--- | :--- |
| 头 | 12 B | magic `CIDX` |
| 记录 | 28 B × n | 16 B hash + **8 B 绝对偏移** + 4 B 压缩长度 |
| 尾 | 16 B | — |

记录数 = `(filesize - 12 - 16) / 28`。

---

## 四、取段算法（块对齐，关键）

```python
lo = idx[hash].offset
hi = lo + idx[hash].compressed_size

lo_al = lo // 4096 * 4096
cnt   = ((hi - lo_al) + 4095) // 4096

# dd if=store.cdb of=x.bin bs=4096 skip=<lo_al//4096> count=<cnt>
# 然后本地从 (lo - lo_al) 处开始切 compressed_size 字节
```

**为什么块对齐**：同一 bundle 的 chunk 在 store 里基本连续，实测 91 个 chunk 落在
3.91 MB 的单段里。逐 chunk 各 dd 一次要走 91 次 IO，块对齐一次就够。

**只读需要的段**：8,776,560 B 的包能拆出 252 个 Texture2D + 252 个 Sprite。
不需要拉 20 GB 整库。

---

## 五、zstd 解压

- 魔数 `28 b5 2f fd`
- 解压后长度**必须等于** `chunks.original_size`
- 不相等 → 段取偏了，回上一步重算，**不要硬拼**

## 六、拼装

```python
parts.sort(key=lambda x: x.file_offset)
acc = 0
for p in parts:
    assert p.file_offset == acc, f"offset 断裂：期望 {acc}，实际 {p.file_offset}"
    buf += p.data
    acc += len(p.data)
```

断言必须留。少了它，拼出来的包 UnityPy 有时仍能 load，但纹理全是花屏——
这是「脚本没报错但结果错」的典型。

---

## 七、adb 的两个硬约束

| 约束 | 原因 |
| :--- | :--- |
| **只用 `adb pull`，不用 `exec-out`** | `exec-out` 的 stdout 会做 LF→CRLF 转换，二进制被写坏**且不报错** |
| **先 `su -c cp` 到 `/sdcard`** | 外部存储对 `shell` 用户不可读 |

批量时设备侧先 `su -c tar` 打包再 pull，减少往返。
