# 剧情三表 · 结构与合并规则

> 全部数字来自 20260813 国际服（sa/152.8.7）实跑，不是估算。

---

## 1. 三张表各管什么

| 表 | 全表行数 | 活动相关行 | 管什么 |
| :--- | ---: | ---: | :--- |
| `Locale_MainScenario` | 150,219 | 89,750 | 主线 `d_main_*`（第 1~48 章）+ **单章式**活动 `event_*` |
| `Locale_SubScenario` | 126,796 | 102,181（其中 `d_contents_*` 3,815） | **多章式**活动 + 支线 / 内容关 / 雪境 |
| `Locale_SideStory` | 11,317 | 11,317（全表） | 番外篇 `s<N>_*` |

列完全一致（11 列）：`Key, ko, en, ja, zh-TW, zh-CN, de, th, fr, es, IsSmart`。

**交付只取 5 语**：`zh-CN / zh-TW / ja / en / ko`。`de/th/fr/es` 有值但不交付（海外小语种，社区无需求）。

## 2. 为什么必须双表合并（血案）

`Locale_MainScenario` 单独导会**整批漏掉只存在于 Sub 的活动**——历史事故漏了 **46 个活动**，
其中一个就是 ce009（PERSONA ON FRONTLINE，3,286 条对话 + 41 条迷你游戏开场 = 3,327 条）。

漏的原因不是「表没读」，而是**默认了「活动都在 Main 里」这个假设**。
判断某活动在哪张表，只能查，不能推：

```sql
select count(*) from Locale_MainScenario where "Key" like 'event\_ce009\_%' escape '\';  -- 0
select count(*) from Locale_SubScenario  where "Key" like 'event\_ce009\_%' escape '\';  -- 3286
```

**结论：活动导出永远同时开 Main + Sub，SQL 同时吃 `event_%` 与 `d_contents_%`。**

只写 `event_` 还会再漏 `d_contents_<活动>_mini_*`（迷你游戏开场文本）。

## 3. 三类活动 key 形态

| 形态 | 例子 | 归属 |
| :--- | :--- | :--- |
| 正篇 | `event_<act>_<章>_<段>_<e\|s>_<句>` | 有章有段，e/s 双轨 |
| 序/间/尾 | `event_<act>_<章>_{prologue\|intermission\|epilogue}_<…>` | 有章无段（序/尾）或段+轨（幕间） |
| 无章的 | `event_<act>_{balloon\|npctalk}_<组>_<句>`、`d_contents_<act>_mini_<组>_<句>` | 无章，排到最后 |

**活动代号字符集是 `[A-Za-z0-9]`，不是 `[a-z0-9]`。**
早期活动是 PascalCase：`BunnyX777`（1,289 条）、`BlueWaterIsland`（26 条）。
写 `[a-z0-9]` 会静默丢 1,315 条 —— 而且脚本**不报错**，只是活动数变小。

**还有一层：分组键必须 `lower()`。** `BlueWaterIsland`(26 条) 与 `bluewaterisland`(62 条)
是同一个活动，按原样分组会得到两个组，而 Windows 目录不分大小写 → 后写的覆盖先写的。
正确做法：按小写分组，目录名用出现次数多的那个原始写法。

### 排序规则

```
STAGE_RANK = {prologue:0,  (正篇)=1,  intermission:2,  epilogue:3,
              balloon:4,  npctalk:5,  mini:6}
TRACK_RANK = {e:0, s:1}
排序键 = [章, 阶段, 段…, 轨]
```

**e / s 是两条并行时间轨**（e = 方舟侧，s = 联动角色侧）。真实交错顺序写在场景脚本里，
**不在 locale 表内**，所以只能按「段 → e → s」排，并在正文里插分隔行标出轨别——
不要假装能还原真实播放顺序。

## 4. 番外篇

### 4.1 篇名不在 `Locale_SideStory` 里

`Locale_SideStory` 只有段落标题（`s4_06_title` 这种），**没有篇名**。
篇名要从 `Locale_Stage` 反查：

```
Locale_Stage:  SIDESTORY_<n>_STAGE_<m>  →  "GINGERBREAD HOUSE-14"
篇名 = 去掉结尾 "\s*-\s*\d+"            →  "GINGERBREAD HOUSE"
```

同一篇有多个 STAGE，取第一个非空即可（各 STAGE 的篇名部分相同）。

### 4.2 键有两种前缀

| 前缀 | 例子 | 覆盖 |
| :--- | :--- | :--- |
| `s<N>_` | `s4_06_1` | 常规 |
| `m_s<N>_` | `m_s004_06_1` | **番外 4 的第 06~10 段，97 条** |

正则必须 `^(?:m_)?s(\d+)_`。只写 `^s(\d+)_` 会让番外 4 从 1,573 条变 1,476 条，
且脚本静默通过。

## 6. 空缺 ≠ 缺失

`Locale_Character` 里 `%_name` 共 1,218 条，简/繁/日/英各空 5 条，韩文 0 条。
空的 5 条是 `quest_npc_9900001_name` ~ `quest_npc_9900005_name`，只有韩文写了
`NPC1`~`NPC5` —— 这是**占位行**，不是漏导。

规则：
- 空缺要**按语言分别统计**，不能只看总数（上面这种就是单语言空缺）
- 看到空缺先看 key 形态：`quest_npc_` / `debug_` / `test_` 一类是占位，不要当 bug 追
- 真缺失的特征是「简中为空但英文有值」且 key 是正常业务 key

## 7. 校验清单

| # | 项 | 通过条件 |
| :-: | :--- | :--- |
| 1 | 不可归组 | `merge_story.py --check` 必须输出 0 条，非 0 就停下来修正则 |

| 5 | 首尾 | 抽 1 个活动，第 1 条是 `prologue` 或 `_1_e_1`，最后一条是 `epilogue` 或最大句号 |
| 6 | 空文件 | 不得出现 0 字节 txt；若某语言整篇为空，记入 `00_规范/未采与放弃.md` |
