# 静态表清单与字段陷阱

> 只列**本期实际查过**的表。没查过的不写，避免下次照抄错字段名。

## 一、`Locale_*.lss` 的结构（实测）

```sql
-- 以 Locale_Character 为例，16443 行
CREATE TABLE Locale_Character (
  Key    TEXT,      -- 如 '10_name'
  ko, en, ja, zh-TW, zh-CN, de, th, fr, es   TEXT,   -- 9 个语言列
  IsSmart INTEGER   -- 富文本标记
);
```

**交付出 5 语**：`zh-CN` / `zh-TW` / `ja` / `en` / `ko`。
表里有 9 个语言列，其余（`de/th/fr/es`）不采，但**不要因为交付 5 语就说表里只有 5 列**。

## 二、技能数值

| 表 | 用途 | 陷阱 |
| :--- | :--- | :--- |
| **`SkillInfoTable`** | **技能数值权威表**，10 级 | 不要用 `SkillTable` |
| `Locale_Skill` | 只有技能名与描述文案，**没有数值** | 数值必须回静态表取 |

链路：`Locale_Skill` 的技能英文名 → 反查 `SkillInfoTable` → 取 10 级数值。
**不许用角色名猜技能 id**，会造成整条链错位。

富文本（`<color=#xxx>` 之类）要转成排版，不能原样贴进 PDF。

## 三、头像框

`UserFrameTable`，字段：

```
Id, ResourceId, SubResourceId, TabType, UserProfileType, FilterType,
Order, NameLocalkey, DescriptionLocalkey, IsSubResourcePrism
```

**一个框可能占多行**：
- 主行：`SubResourceId` 为空
- 部件行：`SubResourceId` = 子资源名，`ResourceId` 与主行相同

基线（152.8.7）：326 行 / 236 个唯一 `ResourceId`，其中
- 冠军竞技场框 7 个，主 + **9 个**部件（`champion_arena_sub_frame_01_01` ~ `_01_09`，7 框共用这 9 张）
- 个突框 27 个，主 + **1 个**叠加层（`icn_soloraid_museum_sub_frame_01_01`，27 框 / 42 Boss 全共用同一张）

判据：`新增框 = 按 ResourceId 聚合后的 (ResourceId, 部件数) 集合差`。
新增个突 Boss = 新增且 `icn_soloraid_<Boss>_tier{1,2,3}_frame` 三行齐全。

> ⚠ 国际服**没有 `icons-dynamic` 合集包**（全桶搜只命中无关的 `dynamicprefabcontroller`）。
> 多部件效果体现在 `SubResourceId` 多行结构，不要再去包里找 dynamic。

## 四、称号（三套体系并存，只查一套必漏）

| # | 表 / 键族 | 基线 | 特征 |
| :-: | :--- | ---: | :--- |
| 1 | `UserTitleTable` | 250 | 图标统一 `icn_usertitle_common`；键 `Locale_System:USERTITLE_NAME_NIKKE_<id>` |

## 五、BOSS 零件（两套命名，最容易混）

`MonsterPartsTable`（基线 715 行）。字段里同时有：

- `PartsSkin` —— 可见网格名（如 `xbga03_1phase_dl_skin`）
- `PartsObject` —— 判定盒名（如 `xba003_1phase_orbiterL_04`）

**同一行里这两个可能完全不同**，混用会对不上任何东西。
判定口径：`PartsSkin` 有值且能在模型包里找到 = 可见；空 = 纯碰撞体，画不出来。

本期实例：安尼希利奥 `451003` = 23 行（19 个命名部件 + 12 个纯判定盒 + 1 条根）；
莉贝雷利奥躯体 `251016` 没有分部判定。

## 六、地图点位

| 表 | 给什么 |
| :--- | :--- |
| `campaignlevelmapgroup` | `PositionId` + 世界坐标，**100% 命中** |
| `<活动>levelmapgroup` | 活动地图点位 |

**不要碰 LDtk**。270 个 `LDtkUnity.LDtkLevelFile` 在 catalog 里但 `data_rowid = 0`，
`internal_id` 是拿不到所属 bundle 的 32 位哈希，且到坐标还要多做一层 `iid → PositionId` 映射。
`campaignlevelmapgroup` 少两步，且已验证。
