# 个人主页装饰：称号 / 头像框 / 名片 badge

## 一、四层，只查一层必漏

| 层 | 表 | 实测 | 字段要点 |
| :-- | :--- | --: | :--- |
| 称号本体 | `UserTitleTable` | 250 行 | `NameLocaleKey` / `IconResourceId` / `UserTitleProductionType` / `UserTitleProductionId` / `RewardId` |
| 称号装配 | `UserTitleAssemblyTable` | 182 行 | `AssemblyType` / `IconId`。**字段名与本体不同**，两表要分别取 |
| 名片 badge | `ProfileCardObjectTable`（`ObjectType=1, ObjectSubType=3`） | 166 行（总表 654） | `ResourceId` 是**裸数字**（如 `"90"`）；名字在 `Locale_Profile:badge_<id>_name` |
| 资料文本 | `Locale_Profile` | — | `title_*` / `badge_*` |

`UserTitleTable` 与 `ProfileCardObjectTable` 是**两条独立下发链**。
只查 `UserTitleTable` 会得出「本期没有新称号」的错误结论。

## 二、`UserTitleTable` 250 行的四块

| Id 段 | 类别 | 条数 | 判法 |
| :--- | :--- | --: | :--- |
| `1~137` | 系统成就 | 40 | `Id` 区间 |
| `201~241` | **活动称号** | 41 | **键后缀 == 活动代号** |
| `1007~5184` | 角色称号 | 169 | 键含 `NIKKE_` |
| `10000~10002` | 特殊 | 3 | `Id >= 10000` |

活动称号可机检，实证：`Id 240 = USERTITLE_NAME_COINRUSHSHOWDOWN` ↔ `EventManager 83400`。

`UserTitleProductionType` 分布：`2:182 / 1:65 / 3:3` —— 分类靠它，不靠猜。

## 三、头像框：必须按 `Id` 差

```
UserFrameTable    326 行 / 236 个唯一 ResourceId
  ├─ icn_soloraid_*        153 行 / 126 唯一 ResourceId / 42 个 Boss 族
  │   （33 族各 3 档，9 族各 6 档 —— 6 档的是带变体的）
  ├─ champion_arena_*      冠军竞技场，不是个突
  └─ Id 20011~20093        27 行博物馆复刻，ResourceId 与旧段 27/27 完全重合
```

**为什么不能按 `ResourceId` 差**：那 27 行复刻框全部复用已有 `ResourceId`，
差集里一个都看不出来 → 误报「本期无新增头像框」。

**也不能 diff 行数**：一个框占 1~10 行，行数变化会掩盖「新增 1 框但删了 2 行」。

正确做法：`{r["Id"] for r in rows}` 做集合差。

## 四、个突族命名不统一，不许按规律判

| 形态 | 例 |
| :--- | :--- |
| 正常 Boss 名 | `icn_soloraid_MotherWhale_tier1_frame` / `icn_soloraid_BlackSmith_*` / `icn_soloraid_gluttony_03_*` |
| 小写混写 | `icn_soloraid_modernia_03_*` / `icn_soloraid_talkative_*` / `icn_soloraid_materialh_*` |
| **纯数字串** | `icn_soloraid_9810811510911663_tier1_frame` |

最后那种**不是脏数据**，是编码过的名字，是一个真实条目，别删。

## 五、用法

```bash
# 一期一次：打快照（退出前跑，作为下一期的基线）
python profile_assets.py --snapshot <基线目录>/00_基线_对象名

# 与基线 diff
python profile_assets.py --baseline <基线目录>/00_基线_对象名 --tsv <输出>/新增清单.tsv
```

脚本内置归族：个突 / 竞技场 / 排行 / 投票 / CE 活动 / 番外。
档位从 `ResourceId` 的 `tier{N}` 读，读不出就标 `—`，不猜。

## 六、判据

| # | 判据 | 通过条件 |
| :-: | :--- | :--- |
| 1 | 四层都有数 | 本体 / 装配 / badge / 文本，各自给出新增数，**0 也写 0** |
| 2 | 头像框用 `Id` 差 | 上报数来自 `Id` 集合差 |
| 3 | 个突三档齐全 | 个突族新增应是 `tier1/2/3` 三条。只出 1~2 条 → 登记「档位不全」，**不补** |
| 4 | 称号名不硬凑 | 名字从 `Locale_System:USERTITLE_NAME_*` 取原文。与候选词不同就是不同 |
| 5 | 基线键非空 | `00_基线_对象名/称号.json` 的 `LocaleKey` 空值为 0，否则先重建快照 |

## 七、坑

| 现象 | 原因 | 处理 |
| :--- | :--- | :--- |
| 称号新增全是 null 名 | 快照取错字段（`IconResource` vs `IconResourceId`） | 重建快照 |
| 头像框新增 0 | 用了 `ResourceId` 差 | 改 `Id` 差 |
| badge 数对不上 | 没按 `ObjectType=1, ObjectSubType=3` 过滤 | 加过滤条件 |
| 装配表字段取空 | 装配表字段名与本体不同 | 两表分别取，别复用同一套键名 |
