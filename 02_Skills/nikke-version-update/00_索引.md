## 装配顺序为什么不能换

```
                     ┌─→ 03 扒资源 ──→ 06 渲动画 ──┐
01 定范围 → 02 取包 ─┼─→ 04 取数据 ─────────────────┼─→ 08 出报告
                     ├─→ 05 文本 ───────────────────┤
                     └─→ 07 重建 3D ────────────────┘
```

- **01 必须在最前**：不定「上期基线」，就没法判定「本期新增」—— 采多了是浪费，采少了要重跑。
- **03 / 04 / 05 / 07 互不依赖**：`04` 只吃静态表 JSON，连包都不用拉，可以和 `03` 同时开工；
  `07` 用 `02` 的战场包，走的是另一套装配逻辑，别和 `03` 的模型导出混在一起。
- **06 必须在 03 之后**：渲的是 `03` 拿到的 `.skel + .atlas + .png` 三件套。
- **08 必须在最后**：它的每个数字都来自前面的产物（见 `08-deliver-pdf/SKILL.md` 第 1 步的表）。

## 编排看板

`03` / `04` / `06` / `07` 各带 `run.py`：把「先跑什么、跑到哪、产物齐没齐」变成一张看板。

```bash
cd 03-asset-extract
python scripts\run.py --status          # DONE / PEND / MAN! / BLOK
python scripts\run.py --run 05          # 只跑某一步
python scripts\run.py --run all --dry    # 先看整条链要跑什么，不动手
python scripts\run.py --run all          # 按序跑，任一步失败就停
```

四条硬规则：

| 规则 | 含义 |
| :--- | :--- |
| **只信产物** | `done` 由「产物存在 + 非空 + 判据通过」推出，**不看有没有跑过**。删产物就是重跑，没有状态文件要清 |
| **手动步骤标 `MAN!`** | 改常量、要人眼看图的步骤，`--run` 只把做法打出来，不假装能自动 |
| **子进程强制 UTF-8** | `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1`，否则中文控制台下 UnityPy / json 里的中文直接炸 |
| **路径只用占位符** | 步骤表里不写 `D:\Codex\...`，一律 `{WORK}` / `{OUT}` 之类，换机器只改环境变量 |

**脚本返回 0 但产物不合格，照样算失败** —— 下游会拿半成品继续，错到最后一页才发现。

| `ADB` | `adb`（platform-tools） |

不设就对应步骤标 `BLOK`，**不会拿上一期的路径去凑**。各 Skill 的 `SKILL.md`「编排看板」一节列全。

```bash
python "D:\Codex\Nikke\Nikke_UpdateMethod\05_脚本\主线\sync_skills.py" --check   # 漂移 + 自足性体检
python "D:\Codex\Nikke\Nikke_UpdateMethod\05_脚本\主线\sync_skills.py" --apply   # 单向同步
```

**自足性**：`SKILL.md` 里写了 `python xxx.py`，`scripts\` 里就必须有它 —— 否则这个 Skill
单独拷走一行都跑不了。体检不通过时 `--apply` 直接拒绝同步，不静默放过。

**脚本分发**：`distribute_scripts.py` 按「入口 + AST 传递闭包」算，不手写依赖清单
（手写必漏：`03` 的 14 个入口自动补出 `nkdb_dec` / `pull_bundle` / `pull_chunks` 3 个）。
