# NIKKE 版本更新采集方法论

把「一次停服更新」变成「一套可验收的素材包 + 一份不会自相矛盾的数据」的完整方法。

不是脚本合集，是**判断流程**：先判范围、再取资源、最后交付。脚本只是每一步的执行器。

> 本仓库由 2026-08 至 2026-10 的十期实战（国际服 8 期 + 国服 2 期）沉淀而来。
> 全部结论都标注了它是「实测」还是「待验」，被推翻的旧结论也留在文档里——**知道什么不成立，和知道什么成立一样重要**。

---

## 一、这套方法解决什么问题

停服更新有四个反复出现的失败模式：

| 失败模式 | 表现 | 根因 |
| :--- | :--- | :--- |
| **采多了** | 交付里塞了一堆上期就有、或下期才上的东西 | 判据用了「客户端里有哪些」而不是「本期新增」 |
| **采少了** | 少角色、少皮肤、少活动，事后补 | 键 diff 口径不一致，或正则写窄了静默丢数据 |
| **数字打架** | 详版说 6 个角色，清单说 5 个，概览说 7 个 | 同一数字在多处各算一次 |
| **交付打不开** | 路径断、图裂、PDF 溢出 | 出完没回读、没逐页看 |

对应的四条原则写死在 `AGENTS.md` §一：**不猜只读 / 一期只对一服 / 只采本期新增 / 一份内容一个物理位置**。

## 二、七步链

顺序不可跳。③ 依赖 ②，④ 依赖 ③；跳过 ② 就无法判「哪些是本期新增」，这是残包的头号原因。

```
① 环境自检 ──→ ② 基线快照 ──→ ③ 键 diff ──→ ④ 取 bundle
   (5 项全绿)   (更新前必须做)   (新增键清单)        │
                                                     ↓
⑦ 交付与自检 ←── ⑥ 归集与文档 ←── ⑤ 解包与渲染 ←────┘
 (逐页/逐帧看)                  (表/文本/GIF/3D)
```

| 步 | 做什么 | Skill | 出口条件 |
| :-: | :--- | :--- | :--- |
| ① | 设备 / 依赖 / 工具链自检 | `01-baseline-diff`（自检段） | 5 项全绿 |
| ② | 更新**前**做全量基线快照 | `01-baseline-diff` | 快照可回读校验 |
| ③ | 新旧 catalog 键集合 diff，按前缀分族 | `01-baseline-diff` | 得出本期新增键清单 |
| ④ | 键 → hash → 设备 cache → 落盘 | `02-bundle-pull` | 每个键都能追到实体文件 |
| ⑤a | 静态表 / 多语文本 / 台词配音 | `03-static-tables` `04-text-locale` | 三表覆盖对照通过 |
| ⑤b | 立绘 / GIF / 3D / 地图 | `05-spine-render` | 全帧网格逐帧看过 |
| ⑥ | 归集交付目录 + 写清单 + 出 PDF | `06-deliver-pdf` | 清单失效 0、PDF 逐页核 |
| ⑦ | 自检 + 简版 PDF + 明细表 | `06-deliver-pdf` | 见 `AGENTS.md` §五 |

六个 Skill 自带 `SKILL.md` + `scripts/` + `reference/`，可单独被 Agent 加载，不依赖本仓库其他部分。

## 三、三条最贵的教训

全量 53 条在 `00_规范/易错清单.md`（A 口径 / B 解析 / C 渲染 / D 交付 / E 迁移 / F 文本与过滤 / G 国服 / H 跨服与期次级 / I 工具链）。时间只够看三条就看这三个：

| ID | 一句话 | 为什么贵 |
| :-: | :--- | :--- |
| **E-01** | 「客户端里有」≠「本期新增」 | 番外篇这么采错过一次，整块返工 |
| **E-05** | 爆裂演出席是**两条** Spine 轨叠加，单播只有局部 | 渲出来「能播但缺一半」，肉眼极易放过 |
| **E-19** | 只验首帧会漏掉坏帧，必须出全帧缩略网格 | 抽查刚好避开坏样本 |

F 类（E-34~E-39）全是「正则写窄了 → 静默丢数据」：脚本不报错，数字变小而已，最容易被当成「本期内容少」放过去。
H 类（E-47~E-50）是「跨服污染 / 官方说新增但包内零变化 / 基线过期 / 一条公告拆成多类资源」，做新一期最先撞上。

## 四、怎么读

**只有 30 分钟** → `AGENTS.md` 的 §一铁律 + §三流程图 + §五验收表。够了，剩下用的时候查。

**有半天** → 加 `00_规范/采集优先级.md`（先采什么）+ `00_规范/易错清单.md` 的 A、H 两类（口径与跨服，返工代价最高）。

**要完整跑一期** → `02_Skills/nikke-version-update/00_索引.md` 按六步走；开工前照 `AGENTS.md` §七答完七问再动手。

**看落地长什么样** → `示例/` 两份真实文档：
- `采集作业令_20261029_国际服.md`——停服前的作战令，八个阶段带时点、出口条件、落盘裁决
- `公告对齐表_20260930_国服.md`——把官方公告 38 条逐条对到包内证据（18 ✅ / 9 ⚠️ / 11 ❌）

## 六、环境常量

一期一改，只改 `00_规范/技术选型.md` 第零节这一处，其余文档引用不复算。

| 常量 | 含义 |
| :--- | :--- |
| `VENV_PY` | 专用 Python（UnityPy / PIL / openpyxl） |
| `ADB` | platform-tools 的 adb |
| `CHROME` | headless Chrome（PDF 打印、CDP 定帧） |
| `PROXY` | CDN 直下时才用，默认不启用 |
| `ROOT` | 本仓库在本机的位置 |
| `WORK` | 当期临时工作区 |
| `CN_ROOT` | 国服链路用（`cn_*.py` 读环境变量） |

两条硬约束：**临时数据不落 C 盘**；**不物理删除**，淘汰物进回收站并附 `_为什么进站.md`。

## 七、适用边界与声明

- 本仓库是**分析与文档方法**，不含游戏本体、不含任何游戏资源文件、不含账号信息。
- `05-spine-render/renderer/vendor/` 属 Spine Runtimes 官方发行文件，受其许可限制，**未包含**；使用前自行按 SKILL.md 放入同版本 runtime。
- 所有解包、解密、比对均针对**本机已授权的客户端副本**，用于版本差异分析与内容整理。请遵守所在地区法律与游戏服务条款，不要用于分发资源或绕过付费内容。
- 结论一期一服、一次一版。客户端布局、加密参数、表结构都可能变，文档里标「待验」的项不要当结论用。

## 八、维护

- 每跑完一期，把新踩的坑按 `E-<序号>` 追加进 `00_规范/易错清单.md`，并在 `AGENTS.md` §六更新计数。
- 被推翻的旧结论不删，移进对应文档的「被推翻的结论」段并写清反证方式。
- 目录结构变动时跑 `05_脚本/主线/check_doc_paths.py`，确认文档里指到的路径都真实存在。
